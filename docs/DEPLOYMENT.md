# Deployment

Everything below is free. Settings are kept in **one place — GitHub →
Settings → Secrets and variables → Actions**. Nothing is typed into Render or
Cloudflare: `.github/workflows/deploy.yml` copies the secrets to Render and
discovers both public URLs on every deploy. Every deploy step is skipped until
its secret exists, so the repo stays green during setup.

A detailed step-by-step walkthrough (in Ukrainian) is in the [README](../README.md).

## 1. Accounts and the secrets they give

| Service | What to do | GitHub Secret(s) |
|---|---|---|
| Turso | `turso db create metravo-control`; `turso db show … --url`; `turso db tokens create …`; `turso auth api-tokens mint metravo`; `turso org list` | `CONTROL_DB_URL`, `CONTROL_DB_TOKEN`, `TURSO_API_TOKEN`, `TURSO_ORG` |
| Firebase | new project → Authentication → enable **Email link** and **Google** → Project settings → Web app config | `FIREBASE_PROJECT_ID`, `FIREBASE_WEB_CONFIG` (one-line JSON, public by design) |
| Telegram | @BotFather → `/newbot`; `openssl rand -hex 32` for the webhook secret | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` |
| Cloudflare | My profile → API tokens → template “Edit Cloudflare Workers”; account id from the dashboard | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` |
| Render | sign in with GitHub → **New → Blueprint** → this repo → Apply (once). Account settings → API keys | `RENDER_API_KEY` |
| OpenTofu state | `openssl rand -hex 32` | `TF_STATE_PASSPHRASE` |

Optional: variable `ADMIN_EMAILS` (your email → the Admin page).

The Cloudflare Pages project is declared in `infra/terraform` and applied by
the workflow; its encrypted state lives on the `infra-state` branch. See
[infra/terraform/README.md](../infra/terraform/README.md) for what is managed
as code and what is not (Render's free tier cannot be).
`JWT_SECRET` is generated by Render (`render.yaml`) and never leaves it.

## 2. Deploy

Actions → **deploy** → Run workflow (afterwards it runs after every green CI on `main`):

1. `tofu apply` in `infra/terraform` → the Pages URL becomes `FRONTEND_URL`;
2. pushes the secrets and `FRONTEND_URL` to Render, starts a deploy, reads the API URL;
3. builds the site against that API URL and publishes it;
4. registers the Telegram webhook.

Set variables `API_URL` / `FRONTEND_URL` only to override the discovered URLs (custom domains).

## 3. After the first deploy

Firebase → Authentication → Settings → **Authorised domains** → add the Pages
domain printed by the “Cloudflare Pages project” step.

## Scanning

The API scans by itself (`SCHEDULER_ENABLED=true` in `render.yaml`): every
minute it runs the searches whose interval has elapsed, and every 10 minutes it
requests its own `/api/health` so Render's free tier never puts it to sleep.
No GitHub schedule, no external cron. `POST /api/scan/cron` with `CRON_SECRET`
remains for anyone who wants an outside trigger.

## Payments

Off for now: `BILLING_PROVIDER=none`, and Pro is shown as “coming soon” until
`PRO_AVAILABLE_FROM` (both in `render.yaml`). To switch on Stripe: add
`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (endpoint
`https://<api>/api/billing/webhook`, events `checkout.session.completed`,
`customer.subscription.updated`, `customer.subscription.deleted`) and
`STRIPE_PRICE_PRO` to GitHub Secrets, then set `BILLING_PROVIDER: stripe` in
`render.yaml`.

## Checks

- `https://<api>/api/health` → `{"status":"ok"}`
- Sign in, save a search, connect Telegram, press “Check now”.
- Plan page: Free 0 zł current, Pro “coming soon”.
